# Studio v2 — nowe UI (Fazy 3–4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nowe, animowane UI w `web/` z widokami Models, Settings i Upscale.
Stare UI zostaje dostępne pod `/legacy/`, a pozostałe widoki linkują do niego,
dopóki nie przejdą do v2 w fazach 5–8.

**Architecture:** SPA (React 19 + TS + Vite) budowana do `web/dist`. FastAPI
serwuje ją pod `/` z fallbackiem SPA i serwuje stary `frontend/` pod
`/legacy/`. Backend z faz 1–2 dostaje tylko drobne uzupełnienia (Task 10). UI
rozmawia wyłącznie z istniejącym API przez typowany klient i TanStack Query.

**Tech Stack:** React 19, TypeScript, Vite, Tailwind v4 (`@tailwindcss/vite`),
shadcn/ui, Motion (`motion/react`), TanStack Query v5, react-router v7, sonner,
lucide-react, `@fontsource-variable/inter` i `@fontsource-variable/jetbrains-mono`,
Playwright 1.65 (chromium jest już w `~/.cache/ms-playwright`), pnpm 11, Node 26.

**Spec:** `docs/superpowers/specs/2026-11-21-studio-v2-design.md`, sekcja
„5. Frontend v2 — `web/`” i lista parytetu. Mapa drogowa faz 3–4 i lista spraw
odłożonych na fazę 3: koniec pliku `docs/superpowers/plans/2026-11-21-studio-v2.md`.

## Global Constraints

- Gałąź robocza to `v2`. Commit po każdym zadaniu, bez pushowania.
- Po każdym zadaniu przechodzi `.venv/bin/python -m pytest -q`. Od Taska 11
  przechodzą też `cd web && pnpm typecheck && pnpm build && pnpm exec playwright test`.
- Teksty UI są po angielsku. Motyw jest tylko ciemny.
- `web/dist/` i `web/node_modules/` są w `.gitignore`. `web/pnpm-lock.yaml`
  jest commitowany.
- Animacje: `MotionConfig reducedMotion="user"` w korzeniu aplikacji.
  Przejścia widoków trwają 150–200 ms, a żadna animacja nie blokuje kliknięć
  (wychodzący widok ma `pointer-events: none`).
- Testy e2e nigdy nie dotykają prawdziwego `.work/`. Serwer testowy dostaje
  `FLUX_PREP_WORK=<katalog tymczasowy>` i port 8131.
- Token HF nigdy nie trafia do `settings.json`, eksportu ani `localStorage`.
  UI pokazuje tylko `tail` z `/api/hf/token`.
- UI nigdy nie startuje pobierania bez folderu wybranego przez użytkownika.
  Jeśli `models_dir == ""`, `DownloadDialog` wymaga wyboru folderu.
- Stare UI pod `/legacy/` działa bez zmian w zachowaniu, jedynym wyjątkiem są
  względne ścieżki zasobów w Tasku 10.
- Kierunek wizualny („studio”, ciemny):
  - tło `#0b0d12`, powierzchnie `#12151c` i `#181c25`;
  - obrysy `rgba(255,255,255,0.07)`;
  - tekst `#e6e8ee`, tekst przygaszony `#8b93a7`;
  - akcent: gradient fiolet→cyjan `#8b5cf6 → #22d3ee`, tylko na aktywnych
    elementach i paskach postępu;
  - stany: sukces `#34d399`, ostrzeżenie `#fbbf24`, błąd `#f87171`;
  - fonty: Inter Variable, JetBrains Mono Variable dla ścieżek i liczb;
  - promień 12 px, delikatny glow akcentu na focusie.

  Tokeny trzymamy jako zmienne CSS w `web/src/index.css` (`@theme`).

## Review Focus

1. **Serwer działa bez zbudowanego `web/dist`** (świeży klon, brak pnpm): `/`
   przekierowuje na `/legacy/` zamiast zwracać 404. Test: Task 10
   `test_root_redirects_to_legacy_without_dist`.
2. **Głęboki link lub odświeżenie na `/settings`** zwraca `index.html`, a nie
   404. Z kolei literówka w `/api/...` daje 404 w JSON, a nie stronę HTML.
   Testy: Task 10 `test_spa_fallback_serves_index` i
   `test_unknown_api_path_is_json_404`.
3. **Błąd API** (400, 409 lub 403 z `detail`) pojawia się jako czytelny toast z
   treścią `detail`, a nie jako „[object Object]” ani cichy brak reakcji. Test:
   Task 14 e2e `models folder error shows toast`, który ustawia folder na
   ścieżkę względną `relative/dir`.
4. **Odpytywanie GPU przy wolnym `nvidia-smi`** nie tworzy kolejki procesów.
   Równoległe żądania `/api/gpus` dzielą jeden odczyt. Test: Task 10
   `test_gpus_concurrent_polls_share_one_smi_run`.
5. **Ustawienie przeżywa przeładowanie:** Models folder, formularz Upscale
   (autozapis) i preset po odświeżeniu strony. Testy: Task 14 e2e
   `models folder survives reload` i Task 15 e2e `upscale form autosaves`.

- [ ] **Step 3: Zaimplementuj**

- **`FLUX_PREP_WORK`.**
  - `server.WORK = Path(os.environ.get("FLUX_PREP_WORK") or ROOT / ".work")`;
  - `settings.CONFIG_PATH` i `gpu.CONFIG_PATH` liczą ten sam katalog z tego
    samego env.

  - Zmieniony warunek: Origin przechodzi, gdy jest loopbackiem i ma ten sam

  - Docstring modułu opisuje nową regułę.
- **`/api/fs/pick`.**
  - Dekorator zmienia się na `@app.post`.
  - W `frontend/app.js:2028` wywołanie dostaje `{method: "POST"}` w formie,

- **`delete_preset`** obcina spacje z nazwy (`name.strip()`), tak samo jak
  `save_preset`.
- **Poller GPU.**
  - `server._smi_snapshot() -> dict` z `threading.Lock`: wątek, który dostał
    lock, wywołuje `gpu.smi_stats()` i zapisuje wynik w `_SMI_LAST`.
    Pozostałe czekają na lock (blokująco) i oddają `_SMI_LAST`, jeśli powstał
    po ich wejściu.
  - `_gpu_status` i `api_gpus` używają `_smi_snapshot()` zamiast
    `gpu.smi_stats()`.
- **`GET /api/upscale/image/{job_id}/{idx}`** korzysta z `_job_of_kind` i daje
  404 „No result.”, gdy nie ma wyniku o tym `idx` albo jego `out_name` jest

### Task 13: Wspólne komponenty

**Files:**
- Create:
  - `web/src/components/FolderPicker.tsx`, `web/src/components/GpuSelect.tsx`;
  - `web/src/components/ModelSelect.tsx`, `web/src/components/DownloadDialog.tsx`;

**Interfaces:**
- Consumes:
  - `GET /api/fs/list?path=&files=weights`: pola `path`, `parent`, `dirs`,
    `is_model`, `free_bytes`, `writable` i opcjonalnie `files`;
  - `POST /api/fs/mkdir {path}`;
  - `POST /api/store/download {model_id, dest}` i
    `POST /api/store/downloads/{id}/cancel`;
  - `PUT|DELETE /api/settings/presets/{view}/{name}` i
    `PUT /api/settings/forms/{view}`.
- Produces:
  - `<FolderPicker open onOpenChange title initialPath? mode?: "dir" | "weights" onPick={(path: string) => void} />`:
    - zawiera breadcrumbs, listę podkatalogów, przycisk `New folder` (pole
      nazwy, potem mkdir), wolne miejsce, odznakę `Read-only`, gdy
      `!writable`, i przycisk `Choose this folder`;
    - w trybie `"weights"` wybiera się plik z `files`.
  - `<GpuSelect value onChange includeDefault?: boolean />`: opcje to
    `Auto (most memory)`, każda karta z `/api/gpus` po etykiecie i `CPU`.
    Przy `includeDefault` dochodzi `Role default` o wartości `""`.
  - `<ModelSelect kind: "vlm" | "florence" | "upscale" value onChange />`:
    - lista z `/api/store/models` dla danego `kind`, z odznaką statusu
      (`ready`, `missing` albo `downloading NN%`);
    - przy `missing` jest przycisk `Download`, który otwiera `DownloadDialog`.
  - `<DownloadDialog modelId open onOpenChange />`:
    - cel podpowiada `settings.models_dir`, a przycisk `Change…` otwiera
      `FolderPicker`;
    - pokazuje wolne miejsce celu i rozmiar modelu, jeśli jest znany;
    - `Download` jest nieaktywny przy pustym celu.
  - `useAutosave<T>(view: string, value: T, delayMs = 500): void` oraz
    `useSavedForm<T>(view: string, defaults: T): [T, setT, loaded: boolean]`,
    który przy wejściu wczytuje `settings.forms[view]` scalone z `defaults`.
