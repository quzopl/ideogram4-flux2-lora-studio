## 2. API

### 2.1 Config / URL / test (SRV:1438-1488)
- Persistence: `.work/comfy_config.json` (`COMFY_CONFIG_PATH` SRV:47): `{url, workflow, mapping, editor_workflow}`; `_load_comfy_config` SRV:1438 returns defaults on missing/corrupt; `_save_comfy_config` writes `indent=2` (non-atomic; every endpoint load-modify-saves the whole file incl. both big workflows — concurrent calls can lose fields, e.g. `generate` for editor vs `/url`).
- `GET /api/comfy/config` (SRV:1459) -> `{url (default http://127.0.0.1:8188 = CC:23), has_workflow, workflow_node_count, mapping}` (no workflow blob). UI uses all four; v2 Settings uses `url` only.
- `POST /api/comfy/url` `{url}` (`ComfyUrlRequest`, SRV:1451; no validation, no scheme check) -> strips + `rstrip("/")`, saves, `{url}`. Empty string is stored as "" and reads back as the default (`cfg.get("url") or DEFAULT_URL`).
- `POST /api/comfy/test` (no body used) -> `{ok:true, url, stats}` where `stats` = ComfyUI `/system_stats` (5s timeout, CC:49); `ComfyError` -> 502 detail e.g. `No connection to <url>: <reason>` / `HTTP 404 z <url>: <body>` (the "z" is Polish, CC:40).
- `GET /api/comfy/loras` (SRV:1525) -> `{loras:[…]}` from `/object_info` `LoraLoader|LoraLoaderModelOnly|LoRALoader` `lora_name` enum (CC:60; 15s timeout; whole `/object_info` downloaded each call, uncached here unlike object_info endpoint); other loader types (rgthree Power Lora) not covered -> `[]`; 502 on `ComfyError`.

### 2.2 Workflow + mapping (SRV:1490-1523)
- `POST /api/comfy/workflow` multipart `file` (SRV:1490): 400 "Empty file."; `comfy_workflows.extract_auto(filename, raw)` (CW:77: `.png` -> `extract_from_png` reads PIL `info["prompt"]|["Prompt"]` tEXt; `.json` -> `_ensure_api_format`; otherwise JSON then PNG) then `autodetect_mapping` (CW:172); any exception -> 400 `Failed to read the workflow: <msg>` (messages for UI-format JSON / PNG without metadata are CW:61-110, English).
   Saves `workflow` + `mapping` into comfy_config (REPLACES previous). Response `{node_count, mapping, source:"png"|"json" (by extension), current_prompt (CW:272: text in the mapped positive node or "")}`.
- `POST /api/comfy/mapping` `{mapping: dict}` (`ComfyMappingRequest`, SRV:1455) -> 400 "Najpierw wgraj workflow." (Polish) when no workflow stored; stores as-is (no validation of node ids/fields) -> `{mapping}`.

### 2.9 What changed since BI (cancel / errors / step text)
- Cancel is real and targeted (SRV:1868, 1616-1636, CC:101-119): the endpoint reads `job.executing`, sets `job.cancel`, then `_comfy_stop(url, pid, executing)`: if executing OR ComfyUI's `/queue` `queue_running` lists the prompt id (`_comfy_prompt_running` SRV:1616) -> `POST /interrupt {"prompt_id": pid}` (newer ComfyUI interrupts only that prompt, older versions interrupt whatever runs); else `POST /queue {"delete":[pid]}`.
   Before the prompt id is known only the flag is set and the runner stops the prompt itself (`_comfy_stream` SRV:1649). Finished jobs: `{ok:true}` no-op. Cancel errors are logged, never raised.
   The state becomes `cancelled` when `stream_events` returns on interrupt/should_stop (checked each second) — the UI's "Cancel" now takes effect within ~1-2 s.
   The legacy UI (and its raw `fetch`) ignores the response; BI's "Cancel is cosmetic" no longer applies.
- `execution_error` (WS) ends the job: `_comfy_stream` returns `"error"`, `job.error` = formatted `"<node_type> (node <id>): <exception_type>: <message>\n<traceback>"` (CC:208), state `error`; same via `/history` fallback `history_failure` (CC:224) when the WS is down (`status_str=="error"` -> "ComfyUI execution error."; `execution_interrupted` -> `cancelled`).
   Therefore `j.error` can be multi-line with a Python traceback: render in a `<pre>`/scroll box.
- History error stop: the `/history` polling loop (0.4s) now exits on a failed prompt instead of waiting forever; `/history` HTTP failure -> state `error`, `error="/history error: <e>"`.
- Step text: raw runner (editor/bbox) `current` = `Step v/m` (was Polish "Krok"), initial `Queueing the workflow…`, then `Finished`; LoRA-test runner `Sample i/N: step v/m`, `Finished (n/N)`. Both start as `Starting…`. `current_node` = id of the executing node (string) — used to highlight a graph node.
- WS-down: both runners catch the WS exception (`WS unavailable (<e>), polling history…`) and continue via `/history` (no progress/preview, `executing` false so the cancel falls back to the queue check).

## 4. Graph view implementation (APP:1785-1887, CSS:166-197)
Plain inline **SVG** built with `document.createElementNS` — no library, no canvas, no pan/zoom/drag, no minimap. It shows the API-format workflow DAG derived only from `[src_id, slot]` input links.
- Layout `layoutGraph` APP:1785: `incoming[id]` = source ids of its link inputs that exist in the workflow; `layer[id]` = longest path from any source (memoised recursion; cycle guard via a per-path `Set` copy returns 0 — exponential on dense DAGs because each call clones the `stack` Set, but fine for typical 20-100 nodes); nodes grouped by layer, sorted by numeric id (`parseInt||0`); constants `NODE_W=170, NODE_H=36, COL_GAP=60, ROW_GAP=24, MARGIN=12`; `x = 12 + layer*(170+60)`, `y = 12 + index*(36+24)`.
   SVG size `W = max(maxX+170, 200)+16`, `H = max(maxY+36, 100)+16`, fixed `width/height` attrs + viewBox; the host `div.ed-graph` scrolls (`overflow:auto; max-height:480px`).
- Links first (under nodes): one cubic Bezier `M x1 y1 C x1+cp y1, x2-cp y2, x2 y2` from the right-middle of the source to the left-middle of the target, `cp = max(30, |dx|*0.4)`, class `ed-link-path` (stroke `#5a6478`, 1.2px, opacity .7); NO arrowheads, no labels for slot/field names, one path per link input.
- Nodes: `g.ed-graph-node[data-node-id]` translate(x,y), `rect 170x36 rx6` (fill `--card2`, stroke `--border` 1.5; hover stroke accent; `.active` fill `rgba(108,140,255,.25)` + accent stroke), text 1 `#<id>` at (8,14) fill `#9aa3b2`, text 2 class_type at (8,28) truncated to 21 chars + "…" (full name not shown as a title tooltip), font 11px monospace. Click -> `focusNode(id)`.
- Rendered only in `hybrid` mode and re-rendered on: tab switch, `renderEditorAll` (load/import/library load/schema refresh). Not re-rendered on field edits (links cannot change in the UI — links are read-only `→ #id` rows). Active highlight: `focusNode` (click) and the job poller (`current_node`) — both just toggle `.active` via querySelector (lost on any re-render).
- Port options: (a) reimplement the same SVG as a React component (~80 lines): compute `layout` with `useMemo([workflow-links])`, map to `<path>`/`<g>` elements, selection/executing state as props (`activeId` from the job poll + clicked id).
   Keeping the layered layout is simplest and identical. (b) a library (e.g. React Flow / dagre) adds a dependency not currently in `web/package.json`; only worthwhile if pan/zoom/drag is wanted.
   Recommendation: (a), memoised on a link signature (not on the whole workflow, so typing into a field does not re-layout), add `<title>` with the full class_type, `role="button"`/keyboard focus, and theme tokens instead of the hard-coded `#11151c`/`#9aa3b2`.
   Make the editor state an immutable store (`setInput(id, field, value)`) rather than mutating the dict in place.

## 6. Fragile / surprising points for the porter
1. **View-entry reload clobbers state**: every `switchView("comfy")` re-runs `loadComfyConfig` (overwrites the typed URL, rebuilds `cLoraRows` to ONE EMPTY row — chosen LoRAs are lost, `cPrompt` and numbers survive because they are not touched) and `loadEditorWorkflowFromServer` (replaces `editor.workflow` with the last GENERATED/uploaded one — unsaved node edits are lost; library loads/imports/edits that were never generated are lost too).
   A React port with state in a store avoids this; decide deliberately what persists (and note `editor.workflow` is only persisted server-side by editor/load and editor/generate).
2. **Gallery order is effectively random**: `sorted(glob("*.json"), reverse=True)` sorts by uuid-hex file name, not by `ts` (SRV:1900). Sort by `ts` descending client-side (the meta has `ts`) or fix the backend. Also the gallery is unbounded and every refresh rebuilds all `<img>`s (lazy-loaded); there is no pagination.
3. **Gallery metadata is thin and inconsistent**: LoRA-test items have no `source`; raw-runner items (editor AND bbox Ideogram renders) have `source:"editor"`, `loras:[]`, seed 0 when the seed is not a literal int (link/`RandomNoise`), prompt "(editor)"/extracted text. No width/height/steps/cfg stored. `filename` is the ComfyUI original (not unique), `id` is the key. `loras` entries are plain strings.
4. **Test connection tests the SAVED url**, not the box content; Save and Test are separate (Settings in v2 only saves). Port: disable/flag Test when the field is dirty, or save-then-test.
5. **LoRA list is never auto-loaded** (only the refresh button; failure leaves free text).
   Rows are uncontrolled free text — a typo is sent as-is and ComfyUI fails at validation ("value not in list" -> `Queueing error: HTTP 400 z <url>: <body>`).
   Only ONE row is created initially even if the mapping has N slots; rows are capped at the slot count; with 0 slots (e.g.
   Power Lora Loader / a workflow with no `lora_name` input) there are NO rows at all and `addLoraRow` shows the "only 0 LoRA loader(s)" error (its `max(slots,1)` allows one row, but `ensureLoraRows` adds none).
   `collectLoras` sends empty strings for blank rows and positions matter (row i -> `lora_nodes[i]`, so removing a middle row shifts the assignments).
6. **No LoRA strength anywhere**: only the name field is patched (`lora_nodes[i].field`); strength/model-only toggles remain whatever the uploaded workflow has. If the port wants "LoRA picker + strength" it requires a backend change (mapping has no strength field) or the editor tab.
7. **Seed semantics**: UI `-1` = random (-> `null`); with batch>1 and a given seed the backend uses `seed+i`; random seeds are 31-bit (`2**31-1`) server-side. The reference batch never sends a seed (random each). The seed that was used is only visible in the gallery meta (`seed`) — the result is not shown inline after a job (the job box only says "Done: N image(s).").
8. **Number inputs are read with `parseInt/parseFloat` without validation**: empty/NaN becomes JSON `null` (-> backend leaves the workflow's own value for width/height/steps/cfg, but `batch: null` -> 422). Width/height are not clamped or snapped to multiples of 64 (step 64 only affects the spinner). `cBatch` max 8 is server-enforced only.
9. **Raw error surfaces**: legacy shows `{"detail":"…"}` JSON text; job errors can contain a Python traceback (`"<e>\n<traceback>"`) or a multi-line ComfyUI traceback (2.9). `DELETE`s use bare `fetch` and ignore failures. Names with `/` cannot be deleted via `/{name}` (path param). `GET /api/comfy/workflows/{name}` likewise.
10. **Mapping JSON is a free-form textarea** with no schema validation; the server stores anything (`dict`). The port should at least keep the raw-JSON editor (the contract is the CW:172 key list) and surface `lora_nodes.length`.
   "Load" of a saved mapping ALSO activates it (POST /mapping); "Save as" does not. Mappings are not tied to a workflow: loading a mapping for another workflow silently mis-patches (nodes missing -> `set_field` no-ops).
11. **Editor value typing is inferred from the current value when no schema**: a float currently stored as `1` (int) gets `parseInt` and step 1 (typing `0.5` becomes 0).
   Empty number -> `null` is written into the workflow (ComfyUI then rejects the prompt). Commit fires on every `input` event. Array values that are not links (len<2 or first element an object) are stringified by the fallback branch.
   Nested dict keys render with `getSchemaForName(k)` only (field-name heuristics). Link inputs are read-only; no add/remove node, no re-wiring.
12. **`/object_info` weight**: multi-MB, fetched on the first editor load per page lifetime and cached 300s server-side; failure is only an info line (cards still render without dropdowns; later `Schemas` click retries).
   `knownEnums` is a global union keyed by field name (bad matches possible). Port: `useQuery(['comfy-object-info'], …, {staleTime: 5*60e3})`, build enums with `useMemo`, and treat the loading/error state explicitly.
13. **Path normalisation is silent**: backslashes in model-file strings are converted both in the editor dropdown (and saved back into the workflow on render) and server-side before queueing (`_normalize_paths`), but NOT when saving to the library/downloading `.json` unless the dropdown render already rewrote it.
14. **Job polling robustness**: `setInterval(…,700)` with no in-flight guard; any single failed poll stops polling permanently, un-busies the UI ("Polling error: …") while the job continues on the server; `jobId` is only in memory (a reload orphans the job; no job-list endpoint).
   The batch card has its own loop that treats network errors as fatal.
   Port: `useJobPoll` (keeps polling on transient errors; 404 -> gone) with `terminal: ['done','error','cancelled']` and keep `jobId` in a module store/sessionStorage so leaving the view resumes (pattern: `pages/bbox/renderStore.ts`).
15. **Cancel UX**: the button stays enabled and the job keeps showing until the poller sees `cancelled`; the status text for that is Polish "Anulowano.". The batch card sets a flag and does not wait.
   Cancel of a `pending` job (before queueing) works through the flag. Two views (card 2 and card 4) can run jobs concurrently (separate pollers, `COMFY_JOBS` is shared); the per-card `comfyJobId`/`editor.jobId` track only the latest.
   ComfyUI itself serialises them.
16. **Preview/progress**: `preview_ts` cache-buster; `#cPrevWrap` stays visible after completion showing the last preview; progress bar resets only on a new job. In the multi-sample runner the `progress.max` resets per sample and speed tracker re-anchors; `eta`/`speed` are 0 until two events. `fmtProgress` formatting in 1.2 should be ported verbatim (`it/s`, `~Xs left`).

(also names a section that no longer exists in v2) / SRV:2028 "Nieznany workflow." / CC:40 "HTTP <code> z <url>: <body>".
   Also Polish code comments/section titles (APP:888, 1303 …).
   The port should use English text; backend messages reach the user verbatim via `ApiError.detail`, so they should be translated server-side (small change + test) or mapped client-side.
18. **Library semantics**: three different stores with different names — mappings and prompts are JSON files keyed by name (overwrite on same name, no confirm, no rename, no timestamps); workflows are SQLite rows keyed by name (upsert, `created` reset on insert only).
   `refreshEdLib` preserves the selection; the mapping/prompt selects do not. Import with a name field filled uses that name; otherwise the file stem (can overwrite an existing entry silently).
19. **Only API-format workflows are accepted** (UI-format JSON with `nodes`+`links` -> 400 with a hint; PNGs carry the API format in the `prompt` tEXt chunk). A `.png` with only `workflow` metadata is rejected.
   Extension decides the parser (`.png`/`.json`), unknown extensions try JSON then PNG. The uploaded file must contain at least one dict with `class_type` as its FIRST value only (sample check) — a workflow with a stray first non-node key passes `_ensure_api_format` only if that first value is a node.
20. **Autodetect limitations affect the LoRA-test card**: no sampler/seed/cfg for `SamplerCustomAdvanced` graphs (seed lives on `RandomNoise`, cfg on `CFGGuider`, steps on a scheduler node), so "Seed", "Steps", "CFG" silently do nothing unless the user edits the mapping JSON by hand; a missing `positive_node` makes the prompt a no-op without any error.
   The UI cannot tell the user which fields are mapped (consider showing mapped/unmapped badges next to each control in the port).
21. **Race/overlap in persistence**: `comfy_config.json` is rewritten whole by `/url`, `/workflow`, `/mapping`, `/editor/load`, `/editor/generate`; the generate worker reads it once at start. Large workflows are written with indent 2 each time. No locking.
22. **Gallery lightbox is a page-level element** reachable from cards 2-5; in React make it a single dialog driven by gallery state (reuse `components/ui/dialog.tsx`), keep Esc/backdrop close, mobile column layout, `download` attr (cross-origin not an issue: same origin `/api/comfy/gallery/<id>`), and clipboard via `lib/clipboard.ts` (`copyText`) instead of the unchecked `navigator.clipboard`.
23. **Backend needs for a faithful port**: none strictly (all endpoints exist).
   Optional improvements the port will likely want: gallery sort by `ts` + `source`/size metadata, LoRA-strength mapping, job list/resume endpoint, translating Polish `detail`s, auto-refresh of the LoRA list (`GET /api/comfy/loras` is cheap enough once per page view but downloads full `/object_info` each call — prefer `/api/comfy/object_info` (cached) and derive loras client-side), invalidating `_OBJECT_INFO_CACHE` on `POST /url` and on explicit schema refresh.
   Tests to add with any backend change: `comfy_workflows` (extract/autodetect/overrides), `/api/comfy/{workflow,mapping,mappings,prompts,workflows,gallery,generate}` with mocked `comfy_client`.

### 7.2 Job state machine (both runners)
`pending` (created, thread starting) -> `running` (worker set it before the first queue call) -> `done` | `error` | `cancelled`.
`error` sources: queue failure ("Queueing error: …"), WS `execution_error` (formatted text, SRV:1663), `/history` failure entry, `/history` HTTP error, unexpected exception (traceback).
`cancelled` sources: cancel flag seen before queueing, `execution_interrupted` WS event, `should_stop` after cancel, `/history` `execution_interrupted`.
A job can still list `images` when `error` is set by a failed `/view` fetch (the job continues and ends `done`; the error text then remains in `error` while `state=="done"` — the legacy UI shows only "Done: N image(s)." in that case, the error is swallowed).
Timing: WS idle timeout 1s ticks (cancel latency <= ~1s); `/history` poll 0.4s; client poll 700ms; ComfyUI HTTP timeouts: test 5s, object_info 15s, prompt 30s, history 10s, queue 5s, view 60s.
