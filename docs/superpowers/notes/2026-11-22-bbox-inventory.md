## 2. Canvas editor internals

### 2.1 Data model (BBX:11, 52-60, 266-281)
Element in memory: `{id: int (monotonic `uid`), type: "obj"|"text", hasBbox: bool, bbox: [y1,x1,y2,x2] (ints/numbers 0-1000), desc: string, text: string, z: int}`. Prompt document built by `buildCaption()` — v15 schema CONFIRMED, key order `aspect_ratio`, `high_level_description`, `compositional_deconstruction{background, elements[]}`; element key order `type`, `bbox` (only if `hasBbox`), `text` (only if type text), `desc`:
```
{"aspect_ratio":"W:H","high_level_description":"","compositional_deconstruction":{"background":"","elements":[{"type":"obj","bbox":[y1,x1,y2,x2],"desc":""},{"type":"text","bbox":[...],"text":"LINE\\nLINE","desc":""}]}}
```
`elements` is emitted sorted by `z` ascending, so **array order == z-order, last = on top** (matches the v15 convention; the editor keeps `z` separate and sorts on output). `text` is a plain string with literal `\n` typed by the user (label says "\n = new line"; no conversion). Empty bbox is allowed (`hasBbox=false` -> key omitted; element has no box on the canvas but still a card). Minified JSON is `JSON.stringify` (no spaces, non-ASCII kept) — server uses `separators=(",",":"), ensure_ascii=False` for the same shape.

### 2.2 Coordinates (BBX:84-101)
Bbox = `[y0,x0,y1,x1]` on a 0-1000 grid, origin top-left, independent per axis (not pixel-proportional). `pxFromBbox`: `left=x0/1000*W, top=y0/1000*H, width=(x1-x0)/1000*W, height=(y1-y0)/1000*H` with `W,H = frame.clientWidth/Height`. `bboxFromPx` rounds to ints, clamps 0-1000, and forces a min 10-unit extent if `x1<=x0`/`y1<=y0`. Default boxes `defBbox` (BBX:84): text `[120,300,300,700]` if ratio>=1.4 else `[120,250,260,750]`; obj wide `[80,400,1000,620]`, tall (ratio<=0.85) `[40,250,1000,750]`, else `[60,300,1000,700]`. Every new element gets the SAME default box (they stack on top of each other; users must drag them apart).

### 2.3 fitFrame (BBX:74-83)
`host = frame.parentElement; pad=32; availW = host.clientWidth-32; availH = max(host.clientHeight-32, 320)`; start `w=availW, h=w*ah/aw`; if `h>availH` then `h=availH, w=h*aw/ah`; style width/height = `max(120, ·)px`. Ends with `render()` (so every `setAR`, window `resize` (BBX:381), `onShow()` and `open()` rebuild everything). No ResizeObserver; the host's own height depends on the frame (flex:1, min-height 340) so there is a feedback loop: the frame is sized from the host height measured BEFORE the new size is applied. A hidden view measures 0 -> hence `BboxEditor.onShow()` from `switchView` (APP:303); width 0 gives frame 120px minimum until shown.

### 2.4 Rendering (BBX:103-121)
`render()` removes all `.bx` nodes and recreates them: class `bx obj|text [sel]`, px geometry, `zIndex = selected ? 1000 : z`, `data-id`, inner `<span class="tag">` ("text: <text or …>" or "obj #id"; CSS ellipsis at 160px) + `<div class="bxh se">` (11px white SE resize handle, CSS:33-34). Then `renderList(); renderJSON(); renderValidation();`. Boxes with `hasBbox=false` are not drawn. Obj = blue border/fill, text = purple `#b07cff` (CSS:24-32). `selectEl(id)` (BBX:163) only toggles classes/zIndex on existing nodes and card `.sel` (no re-render, no scroll of the side list to the selected card).

### 2.5 Pointer interaction
- Single capture-phase `pointerdown` on the frame (BBX:380 `addEventListener(..., true)`, handler 124). Ignores the SE handle (`target.classList.contains("se")`). Computes the click point in frame px, collects all drawn elements whose px rect contains it, **sorted by area ascending** (smallest first), and cycles (below). Selects the chosen element and immediately starts a MOVE drag on it (`startDrag(chosen, ev, false)`).
- Overlap cycling (BBX:123-138): `key = hits.map(id).join(",")` (the SET of ids under the pointer, not the position). If `key === lastHit` -> `lastIdx = (lastIdx+1) % hits.length`, else `lastHit=key, lastIdx=0`. So clicking anywhere inside the same stack of boxes advances the selection; the smallest box is picked first. Clicking in empty space returns early (no deselect, `lastHit` kept). There is no explicit reset when elements move/are deleted, so the next click on a new overlap set restarts at the smallest.
- `startDrag(e, ev, isHandle)` BBX:140: listens on `document` `pointermove`/`pointerup` (no pointer capture, no `touch-action:none` in CSS -> touch drags scroll the page). Move: `left/top = origin + delta`, clamped so the box stays inside the frame; resize (handle): `w=max(8, o.w+dx)`, `h=max(8, o.h+dy)` then the same position clamp (size can exceed the frame; `bboxFromPx` clamps to 1000). Live updates node style + `e.bbox = bboxFromPx(...)` + card readout (`updateBboxReadout` rewrites childNodes[0] of `.bxmini`); on `pointerup`: `renderJSON(); renderValidation()` only (the list/counters not rebuilt). Only the SE corner exists; the handle works only on the already-selected box (BBX:161 `if (e.id !== sel) return`).
- **Keyboard shortcuts: none.** No Delete/Backspace, arrows, Escape, Ctrl+Z, Ctrl+C. **Undo/redo: none.** Delete = card `×` only, no confirm (BBX:230); it removes the element, clears `sel` if it was selected, and re-renders (selection becomes null; no auto-select).
- Z-order (BBX:177): `▲`/`▼` swap the `z` of the element with its neighbour in `z`-sorted order (no-op at ends), `sel=id`, `render()`. New element z = its `uid` (always above), loaded elements z = index+1 (BBX:58). Z values are never renormalised, only used for ordering.
- Add (BBX:183): `uid++`, push `{type, hasBbox:true, defBbox, desc:"", text:"", z:uid}`, select it, render. `uid` is NEVER reset (not even by a load), so card/tag numbers (`obj #7`) are arbitrary monotonic ids, not positions.
- bbox checkbox (BBX:233): turning it ON for an element with no valid bbox assigns `defBbox(type)`; turning it OFF keeps the stored bbox but omits it from output.

### 2.5b Text-field edits (BBX:237-248)
`oninput` writes `e.desc` / `e.text`, updates the on-canvas tag for text, `updateCounters(); renderJSON(); renderValidation()` — no full re-render, so focus is preserved. Head fields: `bxFHld`->`hld`, `bxFBg`->`bg` the same way. EXCEPTION: `bxFAr` (BBX:227) calls `setAR` -> `fitFrame` -> `render` -> `renderList`, which rebuilds the whole side panel including `bxFAr` itself: typing into it loses focus as soon as the text is a valid `W:H` (e.g. while typing `4:5` then continuing).

### 2.6 Load/normalise (BBX:15-64) — CLIENT-side only, see Fragile #2-#5
- `normalize(obj)`: string -> `JSON.parse` (once). For wrapper keys `caption|data|result|output` whose value is an object containing `compositional_deconstruction` or `high_level_description`: recurse into it and copy `aspect_ratio`/`size` from the outer object when the inner lacks them. Then, if `high_level_description` is a string containing `{` and either schema key name, parse `hld.slice(indexOf("{"), lastIndexOf("}")+1)`; if it has `compositional_deconstruction`, recurse. That is the entire "double encoding" handling.
- `loadCaption(raw)` BBX:45: aspect from `aspect_ratio` if `^\d+:\d+$` (trimmed, NOT reduced) else from `size` via `ratioFromSize` (regex `(\d+)\s*[xX*\s]\s*(\d+)`, then gcd-reduced); `hld`, `bg` from `high_level_description` / `compositional_deconstruction.background`; elements mapped to the model above: type text iff `e.type==="text"`; `hasBbox` iff a 4-array; `bbox` via `Number` map (NO clamp / reorder / NaN guard); `desc: e.desc||""`, `text: e.text||""`; `z=i+1`. `hadLegacyStyle` = `style_description` has any of aesthetics/lighting/photo/art_style/color_palette truthy. `sel` = first element id (or null).
- Server equivalent that the client does NOT use: `prompts.normalize_ideogram_v15` (PR:565) + `_unwrap_v15` (PR:539) + `_norm_elements_v15` (PR:517) + `_norm_bbox` (PR:493) + `_norm_aspect_ratio` (PR:479). They are reachable only inside LLM endpoints (`/api/prompt`, `/api/ideogram/analyze`); there is **no endpoint that just normalises a pasted JSON**.

Not in the client: element with a non-dict shape, non-string desc (would throw earlier), the "not valid JSON" / "not a JSON object" errors (client always has a valid model). Not in the backend: nothing. Recommendation for the port: one TS lint module with unit tests that mirror `tests/test_v15_lint.py`, element numbering by array index to match the server, and add the 0-1000 check; keep `V15Findings` as the renderer (accepts `{level,msg}[]`).

## 4. API calls

Legacy bbox code uses bare `fetch` (not the `api()` helper): errors are `new Error(await res.text())`, so users see raw `{"detail":"..."}` text after "Analysis error: " / "Save error: " / "Error: " / "Polling error: " / "Render error: ". The v2 `api<T>` already extracts `detail`.

### 4.1 `GET /api/models` (I2P:23; SRV:685) — only for hybrid/vlm
Response `{"models": {id: label}, "default": "Qwen/Qwen2.5-VL-7B-Instruct"}` (`captioner.AVAILABLE_MODELS` + `custom_models.json` + reachable LM Studio models `lmstudio:<id>` -> "LM Studio: <id>"; SRV:653). Failure: silently no options -> `bxImgModel.value===""` -> `model` omitted from the form (server default `captioner.DEFAULT_MODEL`).

### 4.2 `POST /api/ideogram/analyze` (I2P:56; SRV:2350) — multipart
Form: `file` (the image, required), `engine` (`florence` default | `vlm` | `hybrid`; any other string falls to the florence branch), `model` (only appended if engine != florence AND select has a value; server default `captioner.DEFAULT_MODEL`), `quant` (server default `"4bit"`, **never sent by the legacy UI**; anything not `4bit`/`none` -> `4bit`), `max_tokens` (server default 768, **never sent**). Behaviour:
1. 400 "Upload an image file." if `content_type` empty/not `image/*`; 400 "Failed to read the image." if PIL cannot open it (`convert("RGB")`).
2. `ratio = florence.nearest_aspect(w,h)` among `1:1 4:5 5:4 3:4 4:3 2:3 3:2 9:16 16:9 21:9 3:1 1:3` (log-distance; FL:34, 43).
3. Run in `run_in_threadpool` (blocking; the HTTP request stays open for the whole analysis — first use downloads + loads models; no job id, no progress, no cancel): `florence`: `_ensure_model_http(florence.DEFAULT_MODEL)` (`florence-community/Florence-2-base-ft`) -> `florence.analyze_image` (4 tasks: `<MORE_DETAILED_CAPTION>`, `<OD>`, `<DENSE_REGION_CAPTION>`, `<OCR_WITH_REGION>`; FL:273) -> `build_v15_draft` (FL:156: HLD = caption capped to 50 words at a sentence boundary, **background = the full caption** (duplicate of HLD), elements obj with `desc` = label/region caption and text elements with `desc: 'text "<ocr>"'`, ints bbox, max 40 elements, deduped by IoU>0.85). `vlm`: `_vlm_image_to_v15` (SRV:2263) with `prompts.build_image_v15_instruction()` (PR:851) — the chosen VLM drafts everything, bboxes are its estimates; result passed through `normalize_ideogram_v15(default_ratio=ratio)` (non-JSON output gets wrapped into a minimal schema with the text as both HLD and background). `hybrid`: Florence draft first, then the VLM gets `build_hybrid_v15_instruction(base)` (PR:913) to rewrite prose; `used_model = "<florence> + <model>"`. LM Studio models (`lmstudio:` prefix) go through `lmstudio.caption_image`, local models through `captioner.ensure_loaded(model, quant, source=_ensure_model_http(model))` + `captioner.query_image`.
4. Errors: `lmstudio.LMStudioError` -> 502 "LM Studio: ..."; model-store errors from `_ensure_model_http` -> 400/502 (HTTPException passes through); anything else 500 "Image analysis failed: <e>".
5. Response 200: `{"json": "<minified v15 string>", "elements": int, "model": str, "warnings": [{level,msg}]}`. The client uses `json`, `elements`, `model`, ignores `warnings` (client lint takes over once loaded).
The image is never stored; nothing is persisted; the canvas has no reference-image underlay (the photo is not shown behind the boxes).

### 4.3 `POST /api/prompts/library` (BBX:332; SRV:2205) — Save to library
Body `{category:"ideogram", prompt: JSON.stringify(buildCaption()) (minified), input_text:"bbox editor", action:"manual"}` (model `LibrarySaveRequest`, SRV:243). Server: 400 if category not flux/ideogram, 400 "Empty prompt.", 400 "An Ideogram prompt must be a valid JSON object." (must `json.loads` to a dict); stores stripped prompt; `created=time.time()`. Response `{"id": int, "warnings": [...]}` (warnings ignored by the client). Client success: status "Saved to the library (#id)." (ok) + `window.loadPromptLib()` if defined (APP:859 refreshes `#pLibList` of the Prompt-studio view); failure: "Save error: <raw text>". v2 port: `useMutationWithToast` + `queryClient.invalidateQueries({queryKey:['prompt-library']})`. No dedupe (repeated clicks create repeated rows); no overwrite of a loaded library row (loading from the library creates no link to its id).

### 4.4 `GET /api/ideogram/render/config` (IRR:50; SRV:2296)
Response `{"params": merge_params(stored), "presets": ["Quality","Default","Turbo"]}`; stored file `.work/ideogram_render.json` (SRV:2288) — missing/corrupt -> defaults. Client applies `params` only (failure ignored). `applyConfig` writes seed too, so after a page load the Seed box shows the previous render's seed (and `irRandom` is still checked, so it will be replaced anyway).

### 4.5 `GET /api/comfy/loras` (IRR:57; SRV:1525)
`{"loras": [names]}` from the configured ComfyUI (`/api/comfy/config` url; default `comfy_client.DEFAULT_URL`); 502 `detail` if ComfyUI unreachable (client swallows; field stays free text). Loaded ONCE at page init, never refreshed, so a ComfyUI started later needs a reload.

### 4.6 `POST /api/ideogram/render` (IRR:140; SRV:2303)
Body `IdeogramRenderRequest{prompt: str, params: dict={}}`: `prompt = BboxEditor.getJson()` (minified string), `params` = the 12 keys in 1.5. Server: 400 "The prompt must be a JSON object (v15)." if not a dict (no other validation — lint errors do not block); `params = merge_params(req.params)` (unknown keys dropped; sanitising rules in 1.5/IW:59-83); **persists merged params to `.work/ideogram_render.json`**; `ideogram_workflow.build_workflow(prompt, params)` builds the ComfyUI API graph in Python (IW:134: VAELoader, CLIPLoader type `ideogram4`, two UNETLoaders (cond/uncond), `CLIPTextEncode` on `orientation_lead + "\n\n" + prompt_json`, `ConditioningZeroOut` negative, `EmptyFlux2LatentImage`, `RandomNoise`, `KSamplerSelect`, `CFGOverride`, `DualModelGuider`, `SamplerCustomAdvanced`, `VAEDecode`, `PreviewImage`; `simple` adds `ModelSamplingAuraFlow` + `BasicScheduler(simple)`, `ideogram4` uses `Ideogram4Scheduler`; optional `LoraLoaderModelOnly` spliced on the cond model only). Dimensions from the PROMPT's `aspect_ratio` (not the canvas widget; fallback `1:1`): `compute_dims` IW:86 (area = MP*1024², multiple of 8, latent round-up to 16, floor 256; 3:2@2MP = 1776x1184). Orientation lead IW:97 ("LANDSCAPE/PORTRAIT/SQUARE ... image, WxH pixels" + the bbox coordinate-system sentence). Then a new job in the in-memory `COMFY_JOBS` (SRV:121; shared with the ComfyUI view/gallery) and a daemon thread `_run_comfy_raw_job` (SRV:2039). Response 200 `{"job_id": "<12 hex>", "warnings": lint_v15(prompt)}`. The client puts the warnings into `bxValBox` (replacing the live client lint until the next edit, IRR:148) only when non-empty.
`_run_comfy_raw_job`: state `running`; queue via `comfy_client.queue_prompt(url, workflow, client_id)` (ComfyError -> state `error`, `error="Queueing error: ..."`); `comfy_client.stream_events` over the ComfyUI WebSocket (progress -> `_progress_update` + `current = "Krok v/m"` — **Polish text "Krok"** in this raw runner, SRV:2082; executing -> `current_node`; binary preview frames -> `job["preview"]` PNG bytes + `preview_ts`); then polls `/history` every 0.4s (no overall timeout), fetches each output image from ComfyUI `/view`, saves to `.work/comfy_gallery/<id>.png` + sidecar `<id>.json`, appends meta `{id, filename, seed, prompt, loras:[], ts, url:"/api/comfy/gallery/<id>", source:"editor"}`; final `state="done"`, `current="Finished"`. Meta `seed`/`prompt` are auto-detected from the workflow by `comfy_workflows.autodetect_mapping` (so `prompt` = orientation lead + JSON, `seed` may be 0 if detection fails). Failure -> `state="error"`, `error = "<e>\n<traceback>"` (multi-line). Job output count = latent `batch_size` (one prompt, N images in `images`).

### 4.7 Job endpoints (shared with ComfyUI view; SRV:1784-1830)
- `GET /api/comfy/job/{id}` polled every **700ms** (IRR:151) -> `{id, state, total, done_count, current, current_node, progress:{value,max,speed,eta}, has_preview, preview_ts, images:[meta], error}`. States: `pending` (initial), `running`, `done`, `error`, `cancelled`. 404 "Unknown job." (unknown id, e.g. after server restart; jobs are never evicted otherwise).
- `GET /api/comfy/job/{id}/preview?t=<preview_ts>` -> `image/png` bytes; 404 "No preview." when none. Cache-buster `t` = `preview_ts` float.
- `POST /api/comfy/job/{id}/cancel` -> `{"ok":true}` (404 unknown). It only sets `job["cancel"]=True`, checked in the `/history` polling loop; **no ComfyUI `/interrupt` is ever sent** (grep: none in backend) and `stream_events` blocks until the prompt finishes/errs, so Cancel only takes effect after the render already finished (the images then are not appended? they are fetched only inside the same loop: with cancel set the loop exits with state `cancelled` before collecting). The ComfyUI queue item keeps running.
- Result images: `GET /api/comfy/gallery/{id}` PNG (also list/delete endpoints SRV:1809-1830, used by the ComfyUI view, not the bbox view).
Client `poll()` IRR:99: bar from `progress`; status = `job.current || job.state`; preview shown when `has_preview`; `done` -> `showResults(job.images)` + "Done — image saved to the ComfyUI gallery." (ok); `error` -> "Render error: <job.error || ?>"; `cancelled` -> "Cancelled."; each terminal path calls `stopPolling()` (clears interval, `jobId=null`, un-busy, hides preview, bar 0%).

### 4.8 Not called by the bbox view
`/api/upload`, `/api/gpu`, `/api/prompt`, `/api/prompt-jobs*`, `/api/comfy/generate`, `/api/comfy/test`. The view does not poll GPU and does not call `refreshGpu()` after analyze (the studio does after generate, APP:707) — Florence/VLM run on the local GPU chosen via the header GPU picker (`/api/gpus`, `/api/gpu/select`) and the render runs on the remote ComfyUI, so GPU memory badge staleness only matters for analyze.

## 5. User flows

5.1 **From scratch**: open view (init adds one empty obj at the default box) -> pick an aspect (segmented button or custom text + Enter/blur) -> `+ obj` / `+ text` (each lands on the same default box; select = auto) -> drag (middle) / resize (SE corner of the selected box) -> fill `desc` (and `text` for text elements), HLD and background in the side panel -> watch word counters and the live lint box -> Copy / Pretty / Download / Save to library / Render. Delete via `×`.
5.2 **Paste JSON**: `📥 Paste JSON` opens the bar -> paste -> Load -> `loadCaption` (2.6). Success: bar closes, canvas + side panel + JSON + lint refresh, view re-fitted, first element selected; element list order = array order (z). Failure: red-less (`bxImpMsg` plain `info`) "JSON parse error (...)" and the bar stays open; partially applied state is possible (Fragile #4). The previous canvas is replaced with no confirm.
5.3 **Edit/lint**: typing -> counters + lint update instantly; dragging updates the card readout live and lint on release; overlapping boxes: click repeatedly to cycle (smallest first); `▲▼` change z; bbox checkbox toggles the box off/on.
5.4 **Copy / Pretty / Download / Save**: 4.3 and 1.4. Output always reflects the current `els` sorted by `z`; elements without bbox omit the key.
5.5 **From image — Florence**: click `📷 From image` (or drop an image on the canvas host) -> status "Analyzing the image… First use downloads and loads the model — this can take a while." and the button is disabled -> `POST /api/ideogram/analyze` engine=florence (no model/quant/max_tokens) -> on success `BboxEditor.open(out.json)` -> status "Draft ready: N elements (<model>). Fix the descriptions on the canvas or run it through the studio (Refine) for full v15 descs." Replaces the canvas without confirmation. Descs are short detector labels; BG = whole caption.
5.6 **From image — Hybrid / VLM**: pick engine -> the model select appears (loaded once) -> same flow; `model` is the form field; elements count/model label come from the response (`"Florence-2... + <model>"` for hybrid). Needs the VLM weights (download/load on first use) or a reachable LM Studio (502 otherwise).
5.7 **Render**: (optional) adjust params; LoRA name from datalist -> `🎨 Render canvas`: new random seed if `irRandom`, status "Queueing the render…", button busy, Cancel shown -> `POST /api/ideogram/render` -> `job_id` (+ lint warnings replace the lint box) -> poll 700ms: progress bar + status text + live preview image refresh whenever the job reports `has_preview` (the `src` is reassigned with a new `?t=` every poll — flicker-free only because the same URL changes) -> on `done`: thumbnails prepended to the grid (click opens full PNG in a new tab; also stored in the ComfyUI gallery view), status "Done — image saved to the ComfyUI gallery."; on error: "Render error: …" with a multi-line traceback in `irStatus`.
5.8 **Inbound from other views**: Prompt studio "🧩 Edit on canvas" (APP:741, JSON formats only), library row 🧩 for `category==="ideogram"` (APP:840-848), v2 handoff via sessionStorage (APP:325-335): all do `switchView("bbox")` THEN `BboxEditor.open(json)`; `open` parses with `loadCaption`, sets status "Prompt loaded for editing." or "JSON parse error: <msg>", then `fitFrame()`.

## 7. Fragile / surprising points for the porter
1. **Overlap cycling fires on every pointerdown, including the start of a drag.** If two or more boxes overlap at the cursor, pressing to drag the selected one first advances the selection to the next box (BBX:134-137), so "drag the big box that contains a small one" needs an odd number of presses. A port should cycle only on click-without-move (pointerup with ~0 delta) or Alt/second click, and keep the smallest-first rule.
2. **No pure normaliser server-side**: paste handling is JS-only and weaker than `normalize_ideogram_v15`: no code-fence/prose extraction (`JSON.parse` strict; placeholder text "even broken/double-encoded" overpromises), wrappers only `caption/data/result/output` objects (server also parses string-valued `caption`/`data`), HLD-embedded JSON handled, but a **fully double-encoded top level** (`JSON.parse` yields a string) is not unwrapped: `loadCaption` then loads an EMPTY prompt with no error ("Prompt loaded"). Decide: port to TS with fixtures from `tests/test_ideogram.py`, or add `POST /api/ideogram/normalize` wrapping PR:565 (note PR:565 also reduces `W:H`, accepts `WxH`/`×`, swaps inverted bboxes, flattens dict prose).
3. **Legacy dataset/old formats lose content**: `loadCaption` reads `e.desc`/`e.text` only; elements shaped `{type,description}` / `{type,content}` (old dataset captions) load as empty descs, and type inference `"text" in el` / `"content" in el` (server) is absent. `style_description` is dropped with a warning only.
4. **Non-atomic/unsafe load**: `loadCaption` mutates `ar/hld/bg` before mapping elements; a thrown error (non-array `elements`, non-object element, non-string `desc`/`text`/`hld` -> `.trim` TypeError in `wordCount`/`esc`) leaves a half-loaded editor while reporting "JSON parse error". Bboxes are not clamped/validated/reordered; invalid aspect strings keep the previous `ar`; ratios are not gcd-reduced when given as `W:H`.
5. `uid` never resets and ids appear in card titles/canvas tags; the server lint numbers by array index (see section 3) — pick ONE numbering for the port (recommended: index in z-order, shown on card and tag).
6. **Output order = z order**: `z` is a separate field only to make reordering cheap; the port can drop it and reorder the array, but the on-screen list is ordered bottom-to-top (last card = front) and `▲` = "bring forward" = move later in the array.
7. **Default `defBbox` stacks every new element at the same coordinates**; first element is auto-added on init (an empty obj would be saved/rendered if the user never touches it; lint does not flag an empty-desc obj).
8. **`render()` is a full DOM rebuild** triggered by `fitFrame`, `setAR`, add/delete/z/bbox-toggle; the aspect text input in the side panel loses focus mid-typing (2.5b). In React this is free but keep "typing in desc must not remount cards".
9. `fitFrame` has no ResizeObserver and measures a host whose height depends on the frame; React port should compute from a `ResizeObserver` on the host and keep the frame aspect exact (rounding `max(120,…)` can distort the ratio for extreme ratios like 3:1 in narrow hosts).
10. Pointer handling: document-level listeners, no `setPointerCapture`, no `touch-action:none` (touch devices scroll instead of dragging), handle only active on the selected box, only SE corner (no N/W/E/S handles, no nudging, no keyboard). Min size 8px on resize but 10 units after round-trip.
11. **Clipboard**: Copy buttons call `navigator.clipboard` directly and show "✓ Copied" regardless of success (insecure origin / LAN http fails silently). Use `lib/clipboard.ts` `copyText`. Download writes MINIFIED json despite the "Pretty" button next to it.
12. **Client lint != server lint** (numbering, bbox range, messages, legacy trigger). After Render, the lint box is overwritten with server findings (different numbering) until the next keystroke; a port should render server warnings in a distinct spot or just drop them (they are the same rules on the same JSON).
13. **Render polling robustness**: `setInterval(poll, 700)` has no in-flight guard, so two overlapping polls can both see `state==="done"` and call `showResults` twice (duplicate thumbnails); any transient fetch error stops polling for good and forgets `jobId` while the job keeps running (no Cancel possible, results never shown; they still land in the ComfyUI gallery). `jobId` is not persisted: leaving the view (legacy keeps DOM alive; a router unmount would not) or reloading drops tracking. Use react-query `refetchInterval` keyed by job id, stop on terminal state, survive remount (consider keeping the active `job_id` in the page's store), cap duplicates by keying results by image `id`.
14. **Cancel is cosmetic** (4.7): no ComfyUI interrupt; the UI shows "Cancelled." only once the backend loop sees the flag after the run. The port should either label it honestly or add an interrupt (`POST /interrupt` to ComfyUI) — backend change.
15. **Preview flicker/staleness**: preview `<img>` src changes every poll; `preview_ts` only changes on new frames; after `done` the preview is cleared by `stopPolling` (job's `preview` also set to None). Job statuses for the raw runner are partly Polish ("Krok v/m", "Starting…" initial) — display `current` verbatim or map it.
16. **Render params quirks**: server RESETS (not clamps) out-of-range `megapixels`/`lora_strength` to defaults; `seed` random is generated client-side (≤1e15, safe integer) and saved as the "last seed"; `irRandom` and the form's `cfg/shift/...` are not part of the saved config (and the legacy UI overwrites any hand-edited stored cfg values with defaults on the next render, 1.5 note). Output size is derived from the PROMPT's `aspect_ratio`, so editing the head `aspect_ratio` field directly (valid `W:H`) changes render dimensions; a custom big ratio can make `compute_dims` produce extreme sizes (floor 256, no ceiling beyond MP).
17. **Render is allowed on a lint-failing/empty canvas** (only "is JSON object" checked); batch >1 means N images from one job, not N jobs; the results grid is append-only for the page lifetime (no clear, no per-image delete, no metadata/seed shown); full-size images open in a new tab. ComfyUI availability is only discovered when the job errors (`Queueing error: ...`); loras datalist fetch failing is the only early hint (consider `POST /api/comfy/test` or `/api/comfy/config`).
18. **From image**: request is a single long blocking HTTP call (models download on first use; no timeout handling, no cancel; double-submit prevented only by disabling the button); `quant` and `max_tokens` exist server-side but the UI cannot set them (VLM engines run with 4bit/768 — likely too few tokens for rich v15 JSON, then the wrapper fallback puts raw text into HLD/background); `warnings` returned but unused; the draft replaces the canvas without confirm; Florence background duplicates the HLD caption; drop ignores empty-MIME files (HEIC); no preview of the source photo.
19. Same `bxStatus` element is shared by BBX and I2P (duplicate `setStatus` helpers) — one status slot for load/save/analyze messages; messages are never auto-cleared. `open()` vs Paste-Load differ in the success status (only `open` writes one).
20. **`fetch` errors surface raw JSON text** in legacy; the v2 `api<T>`/`ApiError.detail` + toast is the right replacement (note 422 shape handled by `detailOf`).
21. Library "Save" keeps no id link: re-saving after edits creates a new row; library rows of category `flux` cannot be opened in bbox (only `ideogram`). Handoff semantic to preserve: opening `/bbox` after `handOffToBbox` must consume-and-delete the sessionStorage key once, and invalid JSON must show an error rather than an empty canvas.
22. Backend endpoints needed by a React port exist and need no changes, except optional: `/api/ideogram/normalize` (see #2), render cancel/interrupt (#14), analyze `quant`/`max_tokens` pass-through (already accepted), and (if desired) a job-resume listing (none exists: `COMFY_JOBS` has no list endpoint).
